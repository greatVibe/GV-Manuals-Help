# Work Handoffs

A good handoff lets someone else continue work without guessing. It explains the goal, the current state, what changed, what is blocked, and what should happen next.

This guide covers practical handoffs for projects, documents, spreadsheets, customer work, recurring operations, and tasks that move between people.

## When to use this guide

Use this guide when:

- You are passing work to another person.
- You are going on leave or stepping away from a task.
- A project is moving from planning to delivery.
- A draft, spreadsheet, or file needs review.
- A task is blocked and needs a decision.
- A recurring process needs to continue without you.

## Start with the outcome

Begin by stating what the work is meant to achieve.

Include:

- The purpose of the task or project.
- The expected result.
- Who the work is for.
- Any deadline or important date.

Example:

The goal is to finish the customer summary report by Thursday so it can be reviewed before the Friday meeting.

## Describe the current state

The next person needs to know where the work stands now.

Explain:

- What is complete.
- What is partially done.
- What has not started.
- What has changed recently.
- Which file, draft, or version is current.

Avoid vague phrases such as mostly done or nearly ready unless you also explain what remains.

## Name the next action

A handoff should make the next step obvious.

Use direct wording:

- Review the Summary tab and confirm the totals.
- Add the missing contact details before sending.
- Choose one of the two proposed options.
- Follow up if no response arrives by Wednesday.
- Send the final file after approval.

If there are several next steps, put them in order.

## Separate facts from recommendations

Facts describe what is known. Recommendations explain what you think should happen.

Use this structure when useful:

Facts:

- The draft is complete except for the final figures.
- The source file was updated on Monday.
- Two reviewers have already approved the wording.

Recommendation:

- Wait for the final figures before sending the customer version.

This helps the next person understand what is confirmed and what still requires judgment.

## Include decisions already made

Do not make someone rediscover decisions that have already been settled.

Record:

- What was decided.
- Who made the decision, if relevant.
- When the decision was made.
- Any conditions or limits.

Keep this short. The point is to prevent rework, not to recreate the full discussion.

## Call out blockers

If work cannot continue, say why.

Useful blocker notes include:

- What is blocked.
- Who or what is needed to unblock it.
- When the blocker was identified.
- What has already been tried.
- What should happen next.

Example:

The final spreadsheet cannot be sent until the totals are confirmed. The review request was sent on Tuesday, and the next follow-up should happen Thursday morning if there is no response.

## Link or name the right materials

A handoff should point to the correct materials without making the reader search.

Include:

- File names.
- Folder names.
- Document titles.
- Relevant message threads.
- Version notes.
- Attachments, if appropriate.

Use clear names and avoid linking unrelated files. If a file is private or restricted, confirm that the next person has access before relying on it.

## Protect private information

Only include information the next person needs to do the work.

Do not include:

- Passwords or access tokens.
- Personal information that is not required.
- Private customer data outside the approved file or system.
- Internal notes that should not be forwarded.
- Unrelated files or message history.

If sensitive detail is required, share it through the appropriate secure channel rather than writing it into a general handoff note.

## Keep the format easy to scan

A useful handoff is structured and short enough to read quickly.

Recommended sections:

- Goal
- Current state
- Next action
- Blockers
- Key files
- Decisions
- Deadline
- Contact or owner

For simple tasks, a few bullets may be enough. For complex work, use headings.

## Handoff before time away

When preparing for leave or time away, write the handoff early enough for questions.

Include:

- Work that must continue while you are away.
- Work that can wait.
- People who should be contacted.
- Known deadlines.
- Where important files are stored.
- What should happen if something changes.

A good leave handoff separates urgent work from background work.

## Handoff after a meeting

After a meeting, the handoff should focus on decisions and actions.

Include:

- Decisions made.
- Open questions.
- Owners for each action.
- Due dates.
- Documents or files updated.
- Follow-up meeting, if one is needed.

Do not rely on memory. Send or save the handoff while the details are still fresh.

## Handoff for file review

When handing off a document, spreadsheet, or PDF for review, say what kind of review is needed.

Examples:

- Check the totals only.
- Review wording for clarity.
- Confirm names and dates.
- Compare the file against the source notes.
- Approve or request changes by Friday.

This prevents broad review when only one part needs attention.

Use this template when passing work to another person.

[What this work is meant to achieve]

[What is complete, partial, or not started]

Next action:
[The specific next step]

[What is blocking progress, or write None]

[List the relevant files, links, or message threads]

[Date or timing]

[Person responsible for the next step]

## Quick checklist

Before sending a handoff, confirm that:

- The goal is clear.
- The current state is accurate.
- The next action is specific.
- Blockers are named.
- Relevant files are included or referenced.
- The deadline is visible.
- Private information is not exposed.
- The right owner is named.

## Key takeaway

A strong handoff reduces guessing. State the goal, current state, next action, blockers, and owner so work can continue smoothly.
