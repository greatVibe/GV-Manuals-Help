# Data Validation

Use this guide when checking spreadsheet, table, or CSV data before relying on it, sharing it, or importing it into another system.

Validation helps confirm that data is complete, consistent, and suitable for the intended use.

## Before Validating Data

Before you start, confirm:

- What the data will be used for.
- Which fields are required.
- Which values are expected.
- Whether there is an original source to compare against.
- Whether the file is a draft, working copy, or final version.
- Who should review issues found during validation.

Do not change values during validation unless you are also responsible for cleanup. Keep checking and editing as separate steps when possible.

## Required Fields

Check that required fields are present and filled.

Look for:

- Blank required cells.
- Rows missing key identifiers.
- Columns that should exist but are missing.
- Values marked unknown, not applicable, or placeholder.
- Required dates, names, amounts, or statuses that are empty.

If a blank value may have meaning, confirm whether it means unknown, not applicable, zero, or not yet reviewed.

## Accepted Values

Some columns should only contain known values.

Examples include:

- Status values.
- Categories.
- Yes or no fields.
- Country or region names.
- Product or service names.
- Priority or risk levels.

Check for spelling differences, extra spaces, inconsistent capitalisation, and values that do not match the expected list.

## Date Checks

For dates, confirm:

- Dates use a consistent format.
- Dates are within the expected range.
- Start dates are before end dates.
- Future dates are intentional.
- Blank dates are allowed.
- Day and month order is clear.

If dates affect deadlines, reports, billing, or customer communication, review a sample carefully before sharing.

## Number Checks

For numeric values, confirm:

- Values are in the expected range.
- Decimal places are consistent.
- Negative numbers are intentional.
- Percentages and decimals are not mixed.
- Currency values are labelled clearly.
- Totals match the supporting detail.

Check unusually high or low values. They may be correct, but they should be reviewed before the data is used.

## Duplicate Checks

Check for duplicate records before using or sharing the data.

Confirm what makes a record unique. It may be:

- A single ID.
- A name and date.
- A name and location.
- Several fields together.
- Every field in the row.

Do not remove duplicates during validation unless the duplicate rule is clear and approved.

## Cross-Checks

Use cross-checks to compare related fields.

Examples:

- A total should equal the sum of detail rows.
- A status should match the related date.
- A category should match the item type.
- A quantity should match the unit shown.
- A country should match the currency or region.

Cross-checks are useful for finding errors that are not obvious from one column alone.

## Source Checks

When possible, compare a sample against the original source.

Check:

- A few records from the start, middle, and end of the file.
- Records with blank values.
- Records with high or low numbers.
- Records with unusual statuses.
- Records that changed during cleanup.

If the sample has errors, increase the review before using the file.

## Recording Issues

When validation finds a problem, record enough detail for someone to fix it.

Include:

- Row number or record identifier.
- Column name.
- Current value.
- Expected value or expected rule.
- Why the value may be wrong.
- Whether the issue blocks sharing or use.

Avoid editing uncertain values without approval.

## When To Ask For Review

Ask for review when:

- Data will be shared externally.
- Data affects customer, financial, legal, or operational decisions.
- Required values are missing.
- Many rows fail the same check.
- Duplicate rules are unclear.
- Values appear wrong but the correct value is unknown.
- A validation issue may change a report, import, or decision.

## Quick Checklist

Before using or sharing validated data:

- Confirm required fields are filled.
- Check accepted values and spelling.
- Review dates and number ranges.
- Check duplicates using a clear rule.
- Compare a sample against the source.
- Record issues clearly.
- Do not guess uncertain values.
- Ask for review when the impact is broad or unclear.
